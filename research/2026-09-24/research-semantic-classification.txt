# Evidence dossier: Jev (TypeSafe) and alternatives for semantic three-way decisions

Cutoff is 2026-09-24. Every source below is dated on or before that day. Source IDs [Sx] are listed at the end with URL, date and whether they are vendor or independent. I had no TypeSafe or OpenRouter key, so I made no live Jev inference calls. Every Jev accuracy or latency number here comes from someone else's run, apart from my own network probe [S36].

## 1. Findings

- Jev can propose approve, decline or step_up directly. A 3-option Choice does it, and TypeSafe's integration partners document this pattern (Pydantic's run/reject/ask example [S9], Octomind's allow/ask/block run [S13]). Following the coordinator's instruction, both the direct ternary variant and the fact-decomposition variant stay in the candidate set. The vendor's own guidance and the only relevant independent evidence favour decomposition: atomic questions, arithmetic in code, no multi-factor questions [S5]. That evidence is indirect, and nobody has published a direct head-to-head.
- The strongest independent accuracy result is clean zero-shot classification. On 49 LLM-generated tasks Jev scored 0.966 macro accuracy, and the best local open model scored 0.720 [S11]. The weak results are graded rubric scoring (76.5% vs 84.7% for GPT-5.6 Luna [S12]) and the vendor's own invoice workflow (61.8% vs Sol 79.1% [S7]). The invoice workflow is the closest published task to payment and policy compliance.
- In one test, injected text moved Jev's output substantially. P(block) fell from 0.76 to 0.48 and confidence from 0.64 to 0.22 [S13]. The vendor documents this failure mode itself [S5].
- Latency from Switzerland is bounded below by network distance to AWS Oregon. My probe measured about 0.18-0.20 s warm and 0.52-0.61 s cold, with no inference [S36]. Independent p50 figures are 0.33-0.77 s. One gateway run had a p95 of 29.5 s [S14]. That fits inside the 8 s deadline only if the call has a hard timeout and falls back to something.

### How Noul, Choice and Score confidence are defined

- **Noul** returns one value, `noul`, which is P(yes). There is no separate confidence field [S3], [S6].
- **Choice** returns `choice`, `probabilities` and `confidence`. TypeSafe describes confidence as "a statistic computed from the probability distribution", not a separate learned output [S4]. The docs demo uses (K·p_max − 1)/(K − 1) and calls it an approximation [S4]. All 10 published Octomind rows match this formula to within rounding: 0.55/0.41/0.04 gives 0.33, and 0.76 gives 0.64 [S13]. One 2-option OpenRouter response does not match (p = 0.87 was reported as confidence 0.82, and the formula gives 0.74) [S16]. Recompute the value from `probabilities` and do not rely on the field.
- **Score** returns a probability-weighted `score`, per-level `probabilities`, and `confidence`. TypeSafe says Score levels are "weak in numerical calibration" [S5].
- **Pydantic's adapter** exposes a different "confidence": a margin from the decision threshold, "not a probability that the answer is right" [S9]. Thresholds tuned on one definition do not carry over to the other.
- TypeSafe itself says: "Calibration is measured across groups of predictions; it does not guarantee that an individual answer is correct" (concepts/system-one). It also documents that invariants do not hold. For example, P(refund) plus P(not refund) summed to 1.19 [S5].

## 3. The four earlier assertions

1. **"No labels means we cannot use a classifier."** This is false as stated. Several families need no task labels:
   - Zero-shot classifiers: Jev, NLI models [S22], GLiNER2 [S21].
   - Weak supervision: Snorkel came within 3.60% of hand-curated training sets on average [S30].
   - LLM annotation: zero-shot ChatGPT beat crowd-workers on 4 of 5 tasks [S32].
   - Distillation: a 770M model beat few-shot 540B PaLM on one benchmark using 80% of the data [S31].

   What cannot be done without labels is validating any of these methods or setting its thresholds. The team has to write and adjudicate its own evaluation labels. The history `status` column cannot substitute: the pack's own README reports AUC 0.65 and AP 0.08 on rows where no hard rule fires, and calls `status` an issuer outcome, not fraud truth (`additional-data-history/README.md`).

2. **"Jev cannot output numbers."** This is partly false. Noul returns a float, Score returns a probability-weighted float, and every answer returns probabilities [S3]. What Jev cannot do is generate free-form values. Pydantic rejects unbounded int or float fields [S9]. Value extraction has to be a Choice over candidates that a regex or parser pre-extracted (TypeSafe's "pre-parsed value extraction" cookbook). Arithmetic, counting and date comparison belong in code [S5].

3. **"0.85 is a valid cutoff."** This is unsupported. 0.85 appears as an illustrative "high stakes" threshold in TypeSafe's voice-banking routing example [S4], and Octomind reused it [S13]. TypeSafe states that "correct threshold values depend on your domain... test with your own data" [S4]. With 3 options, confidence 0.85 corresponds to p_max = 0.90; with 2 options it corresponds to 0.925. FlowX measured Choice confidence at 1.00 on a clear contradiction and 0.99 on an ambiguous trace, so it did not separate the two cases [S12]. Any cutoff needs a risk-coverage curve per question, built on team-labelled data.

4. **"70-500 ms will hold from Switzerland."** This is not verified, and the tail is likely to break it. 70-500 ms is the vendor's end-to-end figure measured from the US West Coast [S1]. The measured Geneva-to-Oregon network floor is about 0.18 s warm and about 0.55 s cold, before any inference [S36]. Independent measurements from undisclosed locations:

   | Source | Median | Tail |
   |---|---|---|
   | [S15] | 380 ms | p95 about 670 ms |
   | [S11] | mean about 330 ms | p95 up to about 940 ms |
   | [S12] | 0.77 s | p95 1.13 s |
   | [S10] (OpenRouter listing) | 0.36 s | n/a |
   | [S16] | 239-430 ms (range) | n/a |
   | [S13] | 386-834 ms (range) | n/a |
   | [S14] (gateway) | 367 ms | p95 29.5 s, max 101 s, 9 of 100 calls over 5 s |

   A realistic hypothesis from Switzerland: p50 of 0.3-0.8 s with keep-alive, and an unbounded tail. The 8 s deadline absorbs the median. It does not absorb the tail without a timeout.

Adversarial and structural behaviour:
- In Octomind's single injection test, the verdict stayed `block`, but P(block) dropped from 0.76 to 0.48 and confidence from 0.64 to 0.22 [S13].
- Pydantic's docs say option order "can move the answer" and that "a guard built on Jev belongs alongside deterministic checks" [S9].
- TypeSafe's use-case map lists "detect jailbreaks and prompt injection" as a use case. Its jaggedness page says adversarial state "can move the answer" [S5]. The two statements are in tension.

## 6. Ranked candidates for the semantic sub-layer, with counterevidence

Checking the pack's 45 attempts shows that most decisions depend on structured fields: amounts, rolling spend, `item_category`, `merchant_category`, merchant and device novelty, duplicates. The text-dependent part is `item_details` (size 43 vs 42, road vs trail shoe, "final sale", "return policy not stated", N-day return windows, add-on descriptions, embedded instructions) and whether the item matches the instruction.

1. **Deterministic extraction and rules as the base for every computable fact** (regex for return days and sizes, category fields, arithmetic).
   - For: TypeSafe itself says arithmetic, dates and counting must stay in code [S5]. The approach is immune to injected text.
   - Against: brittle to new wording (German, French or Italian copy, paraphrases). Weak on the "agentic depth" judging axis if used alone.
2. **Jev fact decomposition.** Nouls and Choices over `item_details` and item-vs-request match, with candidates pre-extracted, consumed by code.
   - For: 0.966 macro zero-shot [S11]; tied the LLM on detection [S12]; every model does better in workflow form [S7]; cost is negligible.
   - Against: vendor invoice-workflow agreement of only 61.8% [S7]; injection sensitivity [S13]; option-order sensitivity [S9], [S17]; nondeterminism [S12]; US hosting and tail latency [S14], [S36]; 9 days old, and non-English accuracy is unmeasured [S2].
3. **Jev direct ternary Choice** over {approve, decline, step_up}, with the policy and precomputed facts in the state. It is eligible either as a sole decider or as a cross-check.
   - For: it is the documented pattern [S9], [S13]. In Octomind's run the ordering was sensible across 10 commands.
   - Against: confidence dropped to 0.33 when the policy was missing from the state [S13]. It concentrates the several judgements that [S5] says to split. Errors are correlated within a pass [S12]. It is the most exposed to argumentative text. No published comparison exists against decomposition.
4. **Local zero-shot models (GLiNER2, Von, NLI) as an offline fallback**, optionally few-shot tuned with SetFit on team-written examples.
   - For: 46-163 ms on CPU or MPS [S11], [S21]; no external dependency.
   - Against: 0.58-0.72 zero-shot on out-of-domain tasks [S11]; keyword over-triggering [S11], which is directly relevant to injected text.
5. **Small local LM with a logit readout** (Kev, SemIf, JevLite pattern).
   - For: Kev-9B reached 0.822 vs Jev 0.857 [S18]; runs at 26-64 ms on a GPU.
   - Against: needs a GPU at the venue, adds setup time, and the numbers are self-reported.
6. **Frontier LLM as teacher and label generator, and as an explanation writer off the decision path.**
   - For: the best reference accuracy [S7].
   - Against: 1-3 s per call in the path [S12], or tens of seconds per workflow [S7]. Verbalized confidence evidence is mixed [S25]-[S27].

## 7. Architecture hypotheses (to test, not settled)

- H1: Model outputs should only move a decision toward caution. A model output can raise step_up or decline, and cannot turn a rule-level step_up or decline into approve. If this holds, injected text can cause friction but cannot cause an unsafe approval. It is testable as zero approve-flips under injection.
- H2: Send Jev the normalised facts and a separate, narrowly scoped question about the untrusted text. LangChain's reported PR excludes tool output from the classifier "so content the agent fetched cannot authorize its own execution" [S34]. I did not read the PR itself.
- H3: If the direct ternary answer disagrees with the rule-plus-decomposition decision, the result becomes step_up. This is consistent with the customer instruction "Ask me when uncertain".
- H4: Call Jev in parallel with the rules, with a hard timeout (about 1.5 s) and SDK retries set explicitly. On timeout, 429 or 529, fall back to rules and a local model. Pin `jev-1.13.0`. Log probabilities, option order and model ID.
- H5: Keep one question contract (the `/v1/systemone` schema) so Jev, Kev or Laya can be swapped in, since [S18] and [S19] serve that contract. Expect lower accuracy locally.

## 8. Falsifiable bake-off (fits before the Sep 25 noon submission)

Labels:
- Two team members label all 45 attempts from the instruction text alone, without seeing model outputs. Report Cohen's kappa and adjudicate disagreements.
- Label a perturbation set of about 300 `item_details` variants: paraphrases, German, French and Italian copy, 30 injection styles (a "System:" line, fake JSON fields, pre-authorisation claims, instructions in the merchant name, homoglyph lookalikes). A teacher LLM generates them and humans adjudicate. Label each sub-question: size match, return days, final sale or not stated, add-on present, item matches request, instruction-like text present.

Arms:
- A: rules only
- B: A plus Jev decomposition under H1
- C: Jev direct ternary alone
- D: A plus C as a cross-check under H3
- E: A plus GLiNER2 or Von, local
- F: A plus a small local LM, only if a GPU is available

Metrics:
- Unsafe approvals: approve where the label is decline or step_up. This is the primary metric.
- Needless friction.
- Sub-question accuracy, and Brier and ECE for questions with n ≥ 100.
- Injection flips: whether the decision changes and by how much P changes, with the injected text added to an otherwise identical state.
- Option-order flips.
- Spread over 10 repeated identical calls.
- Latency from the venue network: p50, p95, p99 and max over 200 or more calls, including cold connections, plus the timeout rate.
- Correctness with the network disabled.

Falsification rules:
- "Direct ternary is at least as good" is rejected if C or D has more unsafe approvals or injection flips than B.
- "Jev adds value over rules" is rejected if B does not reduce errors or friction against A on the perturbation set, with Wilson 95% intervals that do not overlap.
- "0.85 is appropriate" is rejected if the risk-coverage curve puts it off the chosen operating point. Zero unsafe approvals in 300 cases gives an upper bound of about 1%.
- "Latency is safe" is rejected if p99 of engine plus model time exceeds about 2 s, or if any fallback yields an approval the rules alone would not.

## 9. Gaps and access constraints

- No API key was available, so there are no live Jev inference results from Switzerland. [S36] measures network time only.
- No public test of Jev on payment or policy-compliance decisions, or on German, French or Italian text.
- No vendor calibration curves.
- No published head-to-head of direct ternary vs decomposition.
- Secondary claims not verified from primary text: the Vercel CEO's "18x faster p95" [bestblogs.dev], the OpenRouter Ori eval (an X post), the Every hands-on test (paywalled), and LangChain PR 40556.
- Most independent Jev sources are 1-9 days old blogs or READMEs with n of 15-866. Competitor READMEs [S18], [S19] benchmark on suites they chose.
- The Tavily search quota ran out partway through; later searches used TinyFish.
- The live judging scenario set is not specified beyond the README note that the live API uses the pack's fixtures.
